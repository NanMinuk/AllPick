# 올픽 (AllPick)

가족 구성원 모두의 입맛에 맞는 식품을 골라주는 AI 추천 서비스

**배포 링크**: https://minuk-kim-20260414.vercel.app/

---

## 기술 스택

| 레이어 | 기술 |
|---|---|
| Frontend | React |
| Backend | Node.js |
| AI | GPT-4o · GPT-4o-mini · text-embedding-3-small |
| DB | MongoDB Atlas |
| 관측성 | LangFuse |
| 호스팅 | Render (백엔드) · Vercel (프론트엔드) |

---

## 핵심 기능

- **가족 프로필 등록** — 구성원별 맵기·알러지·기피재료·선호 음식·식감 입력
- **전체 상품 탐색** — 97개 식품, 카테고리 필터 / 검색 / 페이지네이션
- **AI 추천** — 가족 전체 및 구성원별 탭으로 맞춤 추천
- **구성원별 적합도 판단** — 상품별 적합/주의/부적합 판정 + 상세 근거

---

## 구현 포인트

### Two-stage 추천 파이프라인

에이전트 방식에서 Two-stage 파이프라인으로 전환해 성능을 개선했습니다.

- **Stage 1** — 가족 프로필을 자연어로 변환 후 `text-embedding-3-small`로 임베딩, 사전 계산된 상품 벡터와 코사인 유사도 비교 → 후보 20개 선별
- **Stage 2** — GPT-4o가 후보 20개를 가족 프로필(알러지·기피·선호·맵기) 기준으로 재랭킹

**LLM-as-Judge 평가 결과** (6개 가족 프로필, GPT-4o 블라인드 평가)

| 지표 | 에이전트 | Two-stage | 개선 |
|---|---|---|---|
| 다양성 | 5.0 / 10 | 6.8 / 10 | **+36.7%** |
| 적합도 | 5.2 / 10 | 8.0 / 10 | **+54.8%** |

> 알러지 복합 가족 케이스에서 에이전트는 추천 0개를 반환한 반면, Two-stage는 안정적으로 처리

### 데이터 파이프라인

네이버 쇼핑 API는 성분·알러지 정보를 제공하지 않습니다. 크롤링 시점에 GPT-4o-mini로 상품명을 분석해 주재료·알러지·맵기를 예측 저장하고, 런타임에 해당 예측값을 활용해 할루시네이션을 줄였습니다.

### 추천 Calibration

카테고리별 최대 3개로 제한해 유사 상품 반복 추천을 방지합니다. 적합도 높은 상품은 상위에 유지하면서 간편식·가공식품·신선식품을 고르게 채웁니다.

### 관측성 · 멀티 유저

- LangFuse로 Stage 1/2 각각을 span으로 추적, 레이턴시·비용 모니터링
- 브라우저마다 UUID 발급 → `x-session-id` 헤더로 MongoDB에 세션별 격리 저장

## 어려웠던 점

**추천 상품 선정** — 전체 97개를 프롬프트에 나열하면 토큰 비용이 크고, 검색어를 코드로 고정하면 다양한 가족 구성에 대응이 불가능합니다. 에이전트로 탐색 전략 자체를 LLM에 위임했다가, 최종적으로 Two-stage로 전환해 안정성과 품질을 모두 확보했습니다.

**LLM 응답 품질** — 초기에는 프로필 문구를 그대로 복붙하거나 카테고리명만 반환하는 문제가 빈발했습니다. 판단 우선순위 명시(알러지 → 기피재료 → 맵기 → 취향) + few-shot 예시 + Chain-of-Thought 구조로 해결했습니다.

---

## 아쉬운 점

- **협업 필터링 불가** — 나이대별 실구매 데이터가 있다면 "비슷한 가구가 많이 산 상품"도 함께 추천할 수 있으나, 데이터 부재로 구현 불가
- **구매 이력 미반영** — 가구별 이력을 축적하면 추천 정밀도를 점진적으로 높일 수 있음
- **성분 정보 한계** — GPT 예측에 의존하므로 실제 성분표와 다를 수 있음
